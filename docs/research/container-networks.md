# Container and virtual networks on a Linux host

Research for [#23](https://github.com/dopeCape/better-nm/issues/23). Question: what container/VM networks appear on a Linux desktop, how to enumerate them and their members from an unprivileged user-session daemon, and what an "infra networks" view in `bnm` should show in v1.

Sources are primary (official docs, man pages, upstream source). Facts marked **(local)** were observed on the NixOS dev box (NetworkManager 1.56.0, Docker rootful, user in groups `docker`, `libvirtd`, `networkmanager`).

## 1. What the host actually sees (local baseline)

`nmcli device` **(local)**:

```
wlp4s0            wifi      connected
tailscale0        tun       connected (externally)
br-f1926d4e98a8   bridge    connected (externally)   172.18.0.1/16
docker0           bridge    connected (externally)   172.17.0.1/16
veth124c06c ...   ethernet  unmanaged
```

- `docker network ls` shows `bridge`, `host`, `none` and `mosaic-ai_default` (id `f1926d4e98a8`) — the Compose network is exactly the `br-f1926d4e98a8` bridge NM reports. `/sys/class/net/br-f1926d4e98a8/brif/` lists the two `veth*` ports; `ip neigh` on that bridge gives `172.18.0.2/3 → MAC` for the containers. **(local)**
- NM's D-Bus view of the same bridge: `Device.DeviceType=13` (BRIDGE), `Managed=true`, `Device.Ports=[]` (kernel has two ports, NM lists none because the veths are unmanaged), active connection `StateFlags=253` (includes `EXTERNAL=0x80`), settings profile `Flags=15` (`UNSAVED|NM_GENERATED|VOLATILE|EXTERNAL`) stored under `/var/run/NetworkManager/system-connections/`. The veth: `DeviceType=20` (VETH), `Managed=false`, `State=10` (UNMANAGED), `Device.Veth.Peer="/"` (peer is in the container netns). **(local)**

So NM tells us *that* a bridge exists and is externally configured, but not *whose* it is, nor which containers sit behind it. That mapping has to come from netlink/sysfs plus each runtime's API.

## 2. Per-system findings

### 2.1 Docker (rootful)

- **Enumerate**: Engine API `GET /networks` (list, no `Containers` map since API 1.28) and `GET /networks/{id}` (full `Network`: `Name`, `Id`, `Driver`, `IPAM.Config[].Subnet/Gateway`, `Internal`, `Options`, `Containers{Name, MacAddress, IPv4Address, IPv6Address}`). Containers carry `NetworkSettings.Networks{<net>: EndpointSettings{NetworkID, IPAddress, Gateway, MacAddress, DNSNames, Aliases}}` on both `GET /containers/json` and `/containers/{id}/json`; per-container DNS is `HostConfig.Dns/DnsOptions/DnsSearch`. [Engine API v1.51](https://docs.docker.com/reference/api/engine/version/v1.51.yaml)
- **Actions**: `POST /networks/{id}/connect|disconnect` (body `Container`, `EndpointConfig`; disconnect has `Force`). `GET /events` reports network `create|connect|disconnect|destroy|update|remove|prune`. [ibid.](https://docs.docker.com/reference/api/engine/version/v1.51.yaml), [docker events](https://docs.docker.com/reference/cli/docker/system/events/)
- **Access**: `/var/run/docker.sock` "requiring either `root` permission, or `docker` group membership" ([dockerd](https://docs.docker.com/reference/cli/dockerd/)); "The `docker` group grants root-level privileges to the user" ([post-install](https://docs.docker.com/engine/install/linux-postinstall/)). `srw-rw---- root docker` **(local)**. There is no read-only tier: no socket ⇒ no API at all. `DOCKER_HOST`/`DOCKER_CONTEXT` override the path ([docker CLI](https://docs.docker.com/reference/cli/docker/)); Docker Desktop on Linux uses `~/.docker/desktop/docker.sock` ([Desktop Linux](https://docs.docker.com/desktop/setup/install/linux/)).
- **Host device mapping**: default bridge `docker0` ([dockerd `-b`](https://docs.docker.com/reference/cli/dockerd/)); user-defined bridges are named `"br-" + id[:12]` unless `com.docker.network.bridge.name` is set; host veths are `veth` + 7 random chars ([bridge_linux.go](https://github.com/moby/moby/blob/master/daemon/libnetwork/drivers/bridge/bridge_linux.go), [labels.go](https://github.com/moby/moby/blob/master/daemon/libnetwork/drivers/bridge/labels.go)). Docker's netns files live in `/var/run/docker/netns`, not `/run/netns`, so `ip netns` shows nothing ([namespace_linux.go](https://github.com/moby/moby/blob/master/daemon/libnetwork/osl/namespace_linux.go)).
- **Compose**: network `<project>_default`; `networks.<x>.name` overrides ([Compose networking](https://docs.docker.com/compose/how-tos/networking/)).
- **DNS**: user-defined networks resolve container names via the embedded DNS at `127.0.0.11`; the default bridge copies host `resolv.conf` and cannot resolve peers by name ([Networking overview](https://docs.docker.com/engine/network/), [bridge driver](https://docs.docker.com/engine/network/drivers/bridge/)).
- **Rootless Docker**: daemon runs in a user namespace; net via slirp4netns/pasta/VPNKit/gvisor-tap-vsock; `IPAddress` "is namespaced inside RootlessKit's network namespace … not reachable from the host without `nsenter`" — so its bridges are invisible to the host and to NM. Socket `$XDG_RUNTIME_DIR/docker.sock`, readable by the user with no group ([rootless](https://docs.docker.com/engine/security/rootless.md), [troubleshoot](https://docs.docker.com/engine/security/rootless/troubleshoot.md), [tips](https://docs.docker.com/engine/security/rootless/tips.md)).
- **Go**: `github.com/docker/docker` is deprecated in favour of `github.com/moby/moby/client` + `github.com/moby/moby/api` (Engine 29). `client.New(client.FromEnv)`; version negotiation is on by default; `NetworkList`, `NetworkInspect`, `ContainerList`, `Events` ([release notes 29](https://docs.docker.com/engine/release-notes/29/), [pkg.go.dev](https://pkg.go.dev/github.com/moby/moby/client)).

### 2.2 Podman

- **Stack**: netavark + aardvark-dns since 4.0; CNI is build-tag-gated in 5.0; rootless default switched slirp4netns → pasta in 5.0 ([podman-network](https://github.com/containers/podman/blob/main/docs/source/markdown/podman-network.1.md), [v5.0.0](https://github.com/containers/podman/releases/tag/v5.0.0), [netavark](https://github.com/containers/netavark)).
- **Enumerate**: `podman network inspect` JSON: `name`, `id`, `driver`, `network_interface` (`podman0`, `podman1`…), `subnets[{subnet,gateway}]`, `internal`, `dns_enabled`, `ipam_options` ([network-inspect](https://docs.podman.io/en/latest/markdown/podman-network-inspect.1.html)). Default network `podman` has DNS disabled for Docker compatibility ([basic_networking](https://github.com/containers/podman/blob/main/docs/tutorials/basic_networking.md)). Containers: `NetworkSettings.Networks.<net>.IPAddress/Gateway/MacAddress/Aliases/DNSNames` ([container_inspect.go](https://github.com/containers/podman/blob/main/libpod/define/container_inspect.go)).
- **Rootless**: "unprivileged users cannot create networking interfaces on the host. Therefore, for rootless containers, the default network mode is pasta"; bridge networks run "inside an extra network namespace" reachable only via `podman unshare --rootless-netns` — rootless `podmanN` bridges are **not** host-visible and NM never sees them ([basic_networking](https://github.com/containers/podman/blob/main/docs/tutorials/basic_networking.md), [podman-unshare](https://github.com/containers/podman/blob/main/docs/source/markdown/podman-unshare.1.md), [network-create](https://docs.podman.io/en/latest/markdown/podman-network-create.1.html)). Rootful Podman behaves like Docker (`podman0` bridge on the host).
- **API**: `podman system service` exposes a Docker-compat layer and libpod layer; rootful `/run/podman/podman.sock` (root), rootless `$XDG_RUNTIME_DIR/podman/podman.sock` via `systemctl --user enable --now podman.socket` — unprivileged, no group needed. Routes: `GET /libpod/networks/json`, `/libpod/networks/{name}/json`, `POST …/connect|disconnect`, plus `/networks…` compat ([system-service](https://github.com/containers/podman/blob/main/docs/source/markdown/podman-system-service.1.md), [register_networks.go](https://github.com/containers/podman/blob/main/pkg/api/server/register_networks.go)).
- **Go**: module moved to `go.podman.io/podman/v6`; `bindings.NewConnection(ctx, "unix://…")`, `network.List/Inspect/Connect/Disconnect`, `containers.List/Inspect` ([bindings README](https://github.com/containers/podman/blob/main/pkg/bindings/README.md), [pkg.go.dev v5](https://pkg.go.dev/github.com/containers/podman/v5/pkg/bindings)). Because the compat layer speaks Docker v1.40, the moby client also works against the Podman socket via `DOCKER_HOST` — one client for both is viable.

### 2.3 LXC / Incus

- **Access**: "The root user and all members of the `incus-admin` group can interact with the local daemon" (full control); the `incus` group only reaches the user socket, which maps to a restricted per-user project `user-<uid>` with its own network ([installing](https://linuxcontainers.org/incus/docs/main/installing/#manage-access-to-incus), [incus-user](https://github.com/lxc/incus/blob/main/cmd/incus-user/server.go)). Socket `/var/lib/incus/unix.socket` or `/run/incus/unix.socket` ([connection.go](https://github.com/lxc/incus/blob/main/client/connection.go)). Nothing is readable outside those groups.
- **Enumerate**: `GET /1.0/networks`, `/1.0/networks/{name}` (`type` bridge/ovn/macvlan/physical, `managed`, `used_by` instance URLs, `config` incl. `ipv4.address`, `dns.domain`), `/state`, `/leases` ([rest-api.yaml](https://github.com/lxc/incus/blob/main/doc/rest-api.yaml), [network.go](https://github.com/lxc/incus/blob/main/shared/api/network.go)). `config` is only returned to callers with edit rights ([networks.go](https://github.com/lxc/incus/blob/main/cmd/incusd/networks.go)). Notably `GET /1.0/networks` also lists every *unmanaged* host interface (except `veth*`) with `managed:false` and a sysfs-inferred type — Incus already does the "classify host NICs" job internally ([ibid.](https://github.com/lxc/incus/blob/main/cmd/incusd/networks.go)).
- **Host devices**: default managed bridge `incusbr0` (LXD: `lxdbr0`), NAT + dnsmasq ([initialize](https://linuxcontainers.org/incus/docs/main/howto/initialize/), [network_bridge](https://linuxcontainers.org/incus/docs/main/reference/network_bridge/)); instance NICs `bridged|macvlan|ipvlan|physical|sriov|ovn|p2p|routed`, host side `host_name` random by default ([devices_nic](https://linuxcontainers.org/incus/docs/main/reference/devices_nic/)). NM's udev rule (§3) applies only to `veth*`, so an Incus `host_name` that is not `veth*` might be picked up by NM — worth a defensive `unmanaged-devices` note in docs.
- **Classic LXC**: `lxc-net` creates `lxcbr0` 10.0.3.0/24 with dnsmasq ([lxc-net.in](https://github.com/lxc/lxc/blob/main/config/init/common/lxc-net.in)); `lxc-ls -f` shows IPs but `/var/lib/lxc/<c>` is `0770` so an ordinary user sees only their own unprivileged containers ([lxc-ls](https://linuxcontainers.org/lxc/manpages/man1/lxc-ls.1.html), [lxccontainer.c](https://github.com/lxc/lxc/blob/main/src/lxc/lxccontainer.c)). No API socket; not worth a v1 integration.
- **Go**: `github.com/lxc/incus/v6/client` — `ConnectIncusUnix`, `GetNetworks`, `GetNetworkState`, `GetNetworkLeases` ([pkg.go.dev](https://pkg.go.dev/github.com/lxc/incus/v6/client)).

### 2.4 libvirt

- **Access — the one system with a real read-only tier**: `/run/libvirt/libvirt-sock` (rw, `unix_sock_group="libvirt"`, polkit `org.libvirt.unix.manage`) and `/run/libvirt/libvirt-sock-ro` (`unix_sock_ro_perms="0777"`, polkit `org.libvirt.unix.monitor`) ([daemons](https://libvirt.org/daemons.html), [auth](https://libvirt.org/auth.html), [libvirtd.conf](https://gitlab.com/libvirt/libvirt/-/blob/master/src/remote/libvirtd.conf.in)). Both sockets are `srw-rw-rw-` here **(local)**.
- **What RO gives**: `virConnectListAllNetworks`, `virNetworkGetXMLDesc`, `virNetworkGetBridgeName`, `virNetworkGetDHCPLeases` (guest IP/MAC/hostname) and `virDomainInterfaceAddresses` with source `lease` or `arp` are all `network:read`/`domain:read`, which the ACL doc marks "Anonymous: yes"; only the `agent` source requires a RW connection ([acl](https://libvirt.org/acl.html), [remote_protocol.x](https://gitlab.com/libvirt/libvirt/-/blob/master/src/remote/remote_protocol.x), [libvirt-domain.c](https://gitlab.com/libvirt/libvirt/-/blob/master/src/libvirt-domain.c)).
- **Host devices**: `default` network = `virbr0`, `<forward mode="nat"/>`, 192.168.122.0/24 with dnsmasq DHCP; auto-generated bridges use the `virbr` prefix; guest taps are `vnetN` ("reserved for use by libvirt") ([formatnetwork](https://libvirt.org/formatnetwork.html), [formatdomain](https://libvirt.org/formatdomain.html)). `virsh net-list --all` shows `default inactive` here **(local)**.
- **Session mode** (`qemu:///session`): socket `$XDG_RUNTIME_DIR/libvirt/libvirt-sock`, no RO socket; guests use SLIRP/passt user networking (10.0.2.0/24), no host bridge unless `qemu-bridge-helper` is used ([daemons](https://libvirt.org/daemons.html), [formatdomain](https://libvirt.org/formatdomain.html), [qemu.conf](https://gitlab.com/libvirt/libvirt/-/blob/master/src/qemu/qemu.conf.in)).
- **Go**: `libvirt.org/go/libvirt` is cgo (`pkg-config: libvirt`, or `libvirt_dlopen` tag); `github.com/digitalocean/go-libvirt` is pure-Go RPC with `ConnectListAllNetworks`, `NetworkGetDhcpLeases`, `DomainInterfaceAddresses` ([connect.go](https://gitlab.com/libvirt/libvirt-go-module/-/blob/master/connect.go), [go-libvirt](https://github.com/digitalocean/go-libvirt)). Prefer the pure-Go one for a static `bnm` binary.

### 2.5 systemd-nspawn / machined

- **Host devices**: `--network-veth` → host `ve-<machine>` (15-char limit, hash suffix when truncated); `--network-bridge=` → `vb-<machine>`; `--network-zone=` → auto bridge `vz-<zone>`; macvlan/ipvlan `mv-`/`iv-` ([systemd-nspawn(1)](https://www.freedesktop.org/software/systemd/man/latest/systemd-nspawn.html)). systemd-networkd's `80-container-ve.network` / `80-container-vz.network` give the host side an address, `DHCPServer=yes`, `IPMasquerade=both` ([80-container-ve.network](https://github.com/systemd/systemd/blob/main/network/80-container-ve.network), [80-container-vz.network](https://github.com/systemd/systemd/blob/main/network/80-container-vz.network)) — so on an NM-only host `ve-*` may sit unaddressed.
- **Enumerate**: `org.freedesktop.machine1` `ListMachines()` and `GetMachineAddresses(name)`; both are `SD_BUS_VTABLE_UNPRIVILEGED` with no polkit check, so any user can list machines and their IPs ([org.freedesktop.machine1](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.machine1.html), [machined-dbus.c](https://github.com/systemd/systemd/blob/main/src/machine/machined-dbus.c)). Docker/Podman do not register with machined; nspawn does. Plain `godbus` suffices — no extra library.
- **NM**: `ve-*`/`vb-*` are veths, hence unmanaged via the udev rule (§3). `vz-*` bridges are not matched by any NM rule; treat them like `docker0` (external bridge).

### 2.6 Local Kubernetes

- **kind**: every node is a Docker (or Podman/nerdctl via `KIND_EXPERIMENTAL_PROVIDER`) container on a Docker bridge network named `kind` (`docker network create -d=bridge`, override `KIND_EXPERIMENTAL_DOCKER_NETWORK`); pod CNI `kindnetd` runs inside the nodes, pod CIDR 10.244.0.0/16 ([known-issues](https://kind.sigs.k8s.io/docs/user/known-issues/), [network.go](https://github.com/kubernetes-sigs/kind/blob/main/pkg/cluster/internal/providers/docker/network.go), [configuration](https://kind.sigs.k8s.io/docs/user/configuration/)). From the host this is just a Docker network whose members are node containers; pod IPs are not visible.
- **minikube**: `docker`/`podman` driver → network named after the profile (default `minikube`, subnet from 192.168.49.0); `kvm2` → libvirt network `mk-<profile>`; `none` runs on the host ([kic.go](https://github.com/kubernetes/minikube/blob/master/pkg/drivers/kic/kic.go), [start flags](https://minikube.sigs.k8s.io/docs/commands/start/), [kvm2](https://minikube.sigs.k8s.io/docs/drivers/kvm2/)). So minikube is covered by the Docker/Podman/libvirt paths.
- **k3s**: runs on the host with flannel `vxlan` (cluster 10.42.0.0/16, service 10.43.0.0/16) ([server flags](https://docs.k3s.io/cli/server), [network options](https://docs.k3s.io/networking/basic-network-options)); the bridge is the CNI `bridge` plugin default `cni0` and the VTEP is `flannel.<vni>` ([bridge.go](https://github.com/containernetworking/plugins/blob/main/plugins/main/bridge/bridge.go), [vxlan.go](https://github.com/flannel-io/flannel/blob/master/pkg/backend/vxlan/vxlan.go)). Members are `veth*` pairs into pod netnses; there is no local socket API — pod→IP mapping needs the kube API (out of scope). Calico ships an explicit NM `unmanaged-devices` snippet for `cali*`, `tunl*`, `vxlan.calico`… ([Calico troubleshooting](https://docs.tigera.io/calico/latest/operations/troubleshoot/troubleshooting)); k3s docs have none, so `cni0` will show as "connected (externally)" like `docker0`.

### 2.7 Raw veth / bridge / vlan / vxlan (netlink)

- **Unprivileged reads**: rtnetlink only demands `CAP_NET_ADMIN` for non-GET messages, so `RTM_GETLINK`, `RTM_GETADDR`, `RTM_GETNEIGH` dumps work for any user ([rtnetlink.c](https://github.com/torvalds/linux/blob/master/net/core/rtnetlink.c), [rtnetlink(7)](https://man7.org/linux/man-pages/man7/rtnetlink.7.html)).
- **Attributes that classify a link**: `IFLA_LINKINFO/IFLA_INFO_KIND` (`veth`, `bridge`, `vlan`, `vxlan`, `macvlan`, `tun`, `wireguard`); `IFLA_MASTER` (bridge port → bridge ifindex); `IFLA_LINK` (parent/peer ifindex); `IFLA_LINK_NETNSID` emitted only when the peer is in another netns — the tell-tale of a container veth ([if_link.h](https://github.com/torvalds/linux/blob/master/include/uapi/linux/if_link.h), [rtnetlink.c](https://github.com/torvalds/linux/blob/master/net/core/rtnetlink.c), [ip-link(8)](https://man7.org/linux/man-pages/man8/ip-link.8.html)). `ip -d link` shows `master br-…`, `link-netnsid 0`, kind `veth` **(local)**.
- **sysfs equivalents**: `/sys/class/net/<if>/master`, `/sys/class/net/<br>/brif/`, `iflink`, and the `device` symlink exists only for links with a parent — virtual devices live under `/sys/devices/virtual/net/` ([dev.c](https://github.com/torvalds/linux/blob/master/net/core/dev.c), [if_bridge.h](https://github.com/torvalds/linux/blob/master/include/uapi/linux/if_bridge.h), [core.c](https://github.com/torvalds/linux/blob/master/drivers/base/core.c), [sysfs-class-net](https://github.com/torvalds/linux/blob/master/Documentation/ABI/testing/sysfs-class-net)). **(local)**: `wlp4s0/device → …/0000:04:00.0`; `docker0/device` absent.
- **Member IPs without any runtime API**: the neighbour table (`ip neigh`, `/proc/net/arp`) on a bridge yields IP→MAC of the containers that have talked recently ([ip-neighbour(8)](https://man7.org/linux/man-pages/man8/ip-neighbour.8.html), [proc_net(5)](https://man7.org/linux/man-pages/man5/proc_net.5.html)); the bridge FDB (`RTM_GETNEIGH` on `AF_BRIDGE`) yields MAC→port. Neither gives names.
- **Hard limit**: entering another netns needs `CAP_SYS_ADMIN`, and `/proc/<pid>/ns/net` is readable only under a ptrace-read check ([setns(2)](https://man7.org/linux/man-pages/man2/setns.2.html), [namespaces(7)](https://man7.org/linux/man-pages/man7/namespaces.7.html)). An unprivileged daemon can never look *inside* a container; it can only correlate the host-side ends.
- **Go**: `github.com/vishvananda/netlink` — `LinkList`, `LinkAttrs{MasterIndex, ParentIndex, NetNsID}`, `Link.Type()`, `LinkSubscribe` (events), `NeighList` ([pkg.go.dev](https://pkg.go.dev/github.com/vishvananda/netlink)); `github.com/jsimonetti/rtnetlink` is the lighter pure-netlink alternative ([pkg.go.dev](https://pkg.go.dev/github.com/jsimonetti/rtnetlink)).

## 3. How NetworkManager exposes these devices and how to tell them apart

- **All kernel links appear on D-Bus**, managed or not: `GetDevices()` excludes only "device placeholders" (unrealized), so unmanaged veths are in the list with `State=10` ([Manager](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.html)). **(local)** confirms.
- **Why veths are unmanaged**: shipped udev rule `ENV{ID_NET_DRIVER}=="veth", ENV{INTERFACE}!="eth[0-9]*", ENV{NM_UNMANAGED}="1"` ("managed by libvirt, Docker or the like. Generally we don't want to mess with those"); also `vboxnet*`, `vmnet*`, `vnic*` ([85-nm-unmanaged.rules](https://github.com/NetworkManager/NetworkManager/blob/main/data/85-nm-unmanaged.rules), [NEWS 1.2/1.38](https://github.com/NetworkManager/NetworkManager/blob/main/NEWS)). Since 1.48 the reason is exposed: `NM_DEVICE_STATE_REASON_UNMANAGED_USER_UDEV=77`, `…_EXTERNAL_DOWN=70`, `…_USER_SETTINGS=76` ([nm-dbus-types](https://networkmanager.dev/docs/api/latest/nm-dbus-types.html)).
- **Why bridges are "connected (externally)"**: externally created software devices are unmanaged (`EXTERNAL_DOWN`) until they are up or addressed; then NM generates an in-memory profile and an active connection flagged `NM_ACTIVATION_STATE_FLAG_EXTERNAL=0x80`; the profile carries `NM_SETTINGS_CONNECTION_FLAG_EXTERNAL=0x08|VOLATILE=0x04|UNSAVED=0x01` ([nm-device.c](https://github.com/NetworkManager/NetworkManager/blob/main/src/core/devices/nm-device.c), [NEWS 1.4/1.26](https://github.com/NetworkManager/NetworkManager/blob/main/NEWS), [nm-dbus-types](https://networkmanager.dev/docs/api/latest/nm-dbus-types.html), [Connection.Active](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Connection.Active.html)). nmcli's "(externally)" suffix is exactly that flag ([devices.c](https://github.com/NetworkManager/NetworkManager/blob/main/src/nmcli/devices.c)).
- **Useful D-Bus properties**: `Device.DeviceType` (VLAN=11, BRIDGE=13, GENERIC=14, TUN=16, MACVLAN=18, VXLAN=19, VETH=20, WIREGUARD=29), `Managed` (rw, non-persistent), `Driver`, `Interface`, `Path` (udev `ID_PATH`, empty for virtual), `Ports` (1.34+, replaces `Bridge.Slaves`), `Veth.Peer`, `Tun.Owner/Mode` ([Device](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.html), [Device.Bridge](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Bridge.html), [Device.Veth](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Veth.html), [Device.Tun](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.Tun.html)). Caveat **(local)**: `Ports` is empty for docker bridges because NM only counts ports it manages — bridge membership must come from netlink `IFLA_MASTER`/`brif`.
- **Classifier for "real NIC vs infra"** (all readable unprivileged): real = NM `Path` non-empty / sysfs `device` symlink present / `iflink == ifindex`; infra = kind ∈ {bridge, veth, vlan, vxlan, macvlan, tun} **and** (unmanaged, or active connection has `EXTERNAL`). Then attribute by name/owner: `docker0`, `br-<12hex>` (Docker), `podman[0-9]*` (Podman rootful), `incusbr*`/`lxdbr*`/`lxcbr0` (Incus/LXD/LXC), `virbr*` + `vnet*` (libvirt), `ve-*`/`vb-*`/`vz-*` (nspawn), `cni0`/`flannel.*`/`cali*`/`tunl0` (Kubernetes CNI), `kind` and `minikube` resolve through Docker network names. Names are heuristics; the runtime API is the authority where reachable.
- **Actions to avoid**: `Device.Managed=true` on a docker bridge lets NM activate/deactivate it; `nmcli device delete` removes software devices from the kernel ([Device](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.html), [nmcli(1)](https://networkmanager.dev/docs/api/latest/nmcli.html)). `keyfile.unmanaged-devices` is "strictly unmanaged and cannot be overruled" via API ([NetworkManager.conf(5)](https://networkmanager.dev/docs/api/latest/NetworkManager.conf.html)). None of these belong in an infra view.

## 4. Recommendation

### v1 "infra networks" view — no extra privileges

1. **Source of truth is netlink + sysfs, not NM.** Build a `Link` graph from `RTM_GETLINK`/`RTM_GETADDR`/`RTM_GETNEIGH` (kind, master, link-netnsid, addresses, neighbours), and use NM D-Bus only to mark each link `managed`/`external` and to keep it out of the main "your networks" list. Subscribe with `LinkSubscribe` for live add/remove.
2. **Group by bridge**: one card per external bridge (`docker0`, `br-…`, `virbr0`, `incusbr0`, `cni0`, `vz-…`) showing subnet/gateway from the host address, port count from `IFLA_MASTER`, and IP→MAC neighbours as "N active members". Free-standing `ve-*`/`vnet*`/`flannel.1`/`tunl0` go into a "point-to-point / overlay" bucket. Loose `veth*` with no master are hidden by default (transient).
3. **Attribute the owner by name heuristic** (§3) and label it (Docker / Podman / libvirt / Incus / nspawn / Kubernetes / unknown). Names are the only unprivileged signal for Docker and Incus.
4. **Enrich opportunistically** from APIs that need nothing: machined `ListMachines`/`GetMachineAddresses` (any user), rootless Podman socket (`$XDG_RUNTIME_DIR/podman/podman.sock`, owner only), rootless Docker socket (`$XDG_RUNTIME_DIR/docker.sock`), libvirt `libvirt-sock-ro` (world-readable by default; networks, XML, DHCP leases, `domifaddr --source lease|arp`). Rootless Podman/Docker networks are invisible to netlink, so this enrichment is the *only* way they show up at all — list them as a separate "rootless (not on host)" group.
5. **Inspect only.** No connect/disconnect, no `Managed` flips, no `Delete`, no `Disconnect()` on external bridges. The one safe NM-adjacent action is "explain why this is unmanaged / external" from `StateReason` (1.48+).

### Needs `docker` group (or equivalent) — gated, v1.x

- **Docker rootful** names, Compose project, per-container IP/DNS/aliases, and `connect`/`disconnect`: require socket access, which Docker itself documents as root-equivalent. Detect `/var/run/docker.sock` writability at startup; when absent, show the bridge from netlink with a hint ("add yourself to `docker` to see containers"). Never elevate for this.
- **Incus**: same shape — `incus-admin` for full network view, `incus` only for the user's own project; no read-only path, so treat like Docker.
- **Rootful Podman** (`/run/podman/podman.sock`) is root-only; rootless is the common desktop case and needs nothing.
- **Kubernetes pod membership** (k3s `cni0`, kind pods) needs the kube API, not a host socket — out of scope for `bnm`.
- **Write actions** (`network connect/disconnect`) belong to the runtime's own CLI; if `bnm` ever offers them they should be behind the same socket check and should target the runtime API, never NM.

### Go dependencies implied

`github.com/vishvananda/netlink` (or `jsimonetti/rtnetlink`), `github.com/godbus/dbus/v5` (NM + machined), `github.com/moby/moby/client` (Docker and Podman-compat), `github.com/digitalocean/go-libvirt` (pure Go, RO socket). Incus (`github.com/lxc/incus/v6/client`) and Podman-native bindings (`go.podman.io/podman/v6/pkg/bindings`) are optional, behind build tags or lazy detection.
